# `./traub` — сам інструмент обміну з TX8

Двигун каталогу. **Назовні його не викликають:** входів у каталог рівно два —
[`./send`](HOWTO-send.md) і [`./recv`](HOWTO-recv.md), — і обидва йдуть сюди.
На відміну від каталогу Sinumerik, обгортки нічого не підмінюють: типові
значення вже правильні. Нижче — що саме вони запускають.

```
./traub [--port PORT] {ports|lines|recv|send|renumber} …
```

**`--port` стоїть ПЕРЕД підкомандою.** Обгортки це переставляють самі.

## Підкоманди

| Команда | Що робить |
|---|---|
| `ports` | які послідовні порти видно в системі; порт **не відкривається** |
| `lines` | стан модемних ліній |
| `recv [FILE]` | прийняти програму; без імені — у `./tapes` за O-номером |
| `send FILE` | залити програму |
| `renumber FILE NNN` | побайтово змінити O-номер |

## Прапорці

| Підкоманда | Прапорець | Типово |
|---|---|---|
| `recv` | `--wait` | `600` — скільки чекати першого байта |
| `recv` | `--idle` | `15` — скільки тиші означає кінець. **Не менше 6**: після лідера верстат робить паузу |
| `recv` | `-o` | `tapes/` — куди класти, коли `FILE` не назвали. Разом із `FILE` не задавати: інструмент відмовиться |
| `send` | `--wait` | `600` — скільки чекати `DC1` від верстата |
| `send` | `--resume` | `120` |
| `send` | `--chunk` | `16` |

## Протокол

Мануал Traub, B 2.11 / B 2.12, «Protocol 2», ред. 1.88. Сигнали там підписані
**з боку ЧПК**: DTR/RTS/TXD — це виходи верстата.

**Верстат віддає (B 2.11):**

1. Живлення ЧПК → верстат піднімає DTR.
2. Живлення периферії → верстат бачить DSR.
3. Верстат видає RTS **після отримання CTS**; дані йдуть **після прийому `DC1`**.
4. `DC3` — пауза, `DC1` — відновлення.
5. Після `EOR` верстат приймає `DC3` і знімає RTS.

**Верстат приймає (B 2.12):**

1–2. Те саме з DTR/DSR.
3. Периферія починає передачу, коли активні RTS і `DC1` від верстата.
   **Якщо CTS не активний — верстат `DC1` не видасть узагалі.**
4. `DC3` перериває, `DC1` відновлює.
5. Завершення — `DC3`; усі наступні дані вже не реєструються.

## Лінія

1200 7E1. Апаратний хендшейк **вимкнено** (`-crtscts`). DTR і RTS тримаються
високими статично як «я на звʼязку», побайтовим потоком вони не керують — цим
займаються `DC1`/`DC3`.

Це протилежно каталогу Sinumerik, де все тримається саме на CTS, а `DC1`/`DC3`
не буває взагалі. Числа й звички між каталогами не переносити.

## Формат стрічки

```
100 × NUL      leader (чиста стрічка)
%              маркер початку
10 × NUL
CRLF
O33            номер програми
(PROGRAMNAME-11861)
…G-код, рядки через CRLF…
M30
10 × NUL
%              маркер кінця
100 × NUL      трейлер
```

Рядки — **CRLF**, не LF.

## Чого не робити

1. **Не слати `DC3` «на підтвердження» наприкінці прийому** — там це «пауза».
2. **Не правити стрічку текстовим редактором наосліп** — він вносить байти >127
   і губить `%`. Саме тому `send` це перевіряє й відмовляється. Зразки поломок —
   у `tapes/_broken/`.
3. **Не зменшувати `--idle` нижче 6** — обірветься після лідера, а виглядатиме
   як успішний прийом.
