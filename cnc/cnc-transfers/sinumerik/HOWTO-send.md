# `./send` — віддати програму на стійку

Обгортка над `./sinumerik send`. Має два режими й підставляє для кожного свій
набір параметрів, щоб не тримати їх у голові біля верстата.

| Режим | Команда | Що робить стійка |
|---|---|---|
| заливка в памʼять | `./send ФАЙЛ` | зберігає програму під номером із заголовка |
| **BTR**, пряме виконання | `./send --dnc ФАЙЛ` | виконує кадри прямо з дроту, нічого не зберігаючи |

## Найкоротше

```
cd ~/cnc-transfers/sinumerik
./send test/test4.nc            # у памʼять
./send --dnc test/test5.nc      # виконати з дроту
```

**Спершу команда, потім `START` на стійці.** Не навпаки — якщо стійка вже в
прийомі, коли інструмент відкриває порт, початок передачі губиться.

## Що вона підставляє

Заливка в памʼять:

| Прапорець | Значення | Навіщо |
|---|---|---|
| `--gate` | `90` | чекати `START` на стійці |
| `--wait` | `0` | не чекати `DC1` — ця стійка його не шле |
| `--stall` | `1000` | терпіти опущений CTS посеред передачі |
| `--gcode` | увімкнено | розбір під керуючу програму |

`--dnc` (BTR):

| Прапорець | Значення | Навіщо |
|---|---|---|
| `--gate` | `300` | 5 хвилин на послідовність `BTR START` → `NC START` |
| `--wait` | `0` | `DC1` стійка не шле; передачу відкриває підняттям `CTS` |
| `--first` | `90` | півтори хвилини на **перший** байт, далі помилка |
| `--stall` | `0` | після першого байта — чекати скільки треба, **без таймауту** |
| `--resume` | `0` | те саме для `XOn` після `XOff` |
| `--linger` | `15` | дослухати лінію після останнього байта |
| `--gcode` | увімкнено | розбір під керуючу програму |

Своє значення завжди переважає: `./send --dnc --gate 30 файл.nc` дасть саме 30.

Порт прокидається як є: `./send --port /dev/ttyS0 файл.nc`. Без нього — авто­визначення, і лише якщо порт у системі рівно один.

### Чому в BTR нема таймаутів після першого байта

Стійка виконує кадри одразу й паралельно набиває circular buffer. Коли той
повний — спиняє потік, поки не звільнить місце вже виконаними кадрами. Пауза тут
означає **роботу верстата**, і її тривалість залежить від програми. Обрив по
таймауту вбив би справний прогін на середині.

Перший байт — інша річ: поки він не пройшов, ніщо не доводить, що стійка взагалі
в прийомі. Там таймаут лишається.

### `--dnc` у ядро не передається

Окремого DNC-формату в потоці не існує. Кадри ті самі, що й при заливці в
памʼять, разом із `%MPF…`-заголовком — стійка звіряє по ньому номер програми
(аларм 33). `--dnc` тут лише імʼя набору параметрів.

`--trim-tail` (файли відновлення) вимикає підстановку `--gcode`: в інструменті
`--gcode` переважає `--trim-tail`, тож тиха підстановка зіпсувала б заливку
TEA/PCP/ASM. Разом із `--dnc` він відхиляється — файли відновлення не програми
й з дроту не виконуються.

Перед запуском друкується повна команда — видно, що саме пішло на верстат.

## Порядок дій на стійці — заливка в памʼять

1. `DATEN EIN-AUS` → `DATEN-EINGABE`
2. `Eingabeschnittstelle` ← `1`
3. запустити `./send …` на лаптопі
4. `START` (софткнопка 4)

Стійка спиняється сама на `M02`/`M30`. Програма лягає під тим номером, що в
заголовку: `%MPF0003` → `MPF 3`.

## Порядок дій на стійці — BTR

1. запустити `./send --dnc ФАЙЛ` на лаптопі
2. режим `AUTOMATIC`
3. в основному екрані `AUTOMATIC` ввести номер програми — той, що в заголовку
   файлу (`%MPF0005` → `5`). Або `0`: тоді номер не звіряється й аларму 33 не буде
4. `DATEN EIN-AUS`, задати `Eingabeschnittstelle`. **`START` тут НЕ тиснути** —
   інтерфейс лишається заданим, але не запущеним. Вийти з меню
5. `BTR START`
6. `NC START`

Виконання починається одразу, не чекаючи, поки набереться буфер.

**Перевір `Einzelsatz`,** перш ніж дивуватись, чому воно йде по кадру: тумблер на
нижній панелі має стояти в `O`, а `DEK-ES` у меню `PROGRAMMBEEINFLUSSUNG` — у
`NEIN`. Ознака на екрані — `HALT: Einzelsatz`.

## Що видно на екрані

```
+ /home/…/sinumerik --port /dev/ttyUSB0 send --stall 1000 --wait 0 --gate 90 --gcode test/test4.nc
port /dev/ttyUSB0 auto-detected  (USB  usb-FTDI_…)
9600 7E1  crtscts=on  files: 1
test4.nc: gcode: 10 blocks, source file has CRLF, stripped 17 spaces
  >>> PUSH START — test4.nc: control ready to receive  0:05
[1/1] test4.nc  sent 320 B in 0.4 s
```

`>>> PUSH START` означає «стою на гейті, чекаю тебе».
`!` і лічильник `СТОП m:ss` посеред передачі — стійка попросила паузу, це норма
на великих файлах. Мертву лінію видно по тому, що лічильник росте й не спиняється.

## Кілька файлів за раз

```
./send --trim-tail RV001-restore/TEA1.NC RV001-restore/TEA2.NC
```

Порт лишається відкритим **наскрізь**, через усі файли. Це принципово: коли він
закривався між файлами, на стику виникала сліпа дірка на кілька секунд, і
натиснутий у неї `START` губився. Перший файл чекає `CTS=1`, решта — переходу
`1→0→1`, тобто стійка мусить вийти з прийому й увійти знову.

Заливку шести файлів відновлення робить окремий `RV001-restore/restore.sh`.

## Типові відмови

| Повідомлення | Що сталось |
|---|---|
| `REFUSED: N bytes >127` | у файлі байт понад 127, а канал 7-бітний. Зазвичай текстовий редактор зіпсував файл |
| `CTS never rose: START was not pressed` | вичерпався `--gate`, стійку в прийом не ввели |
| `CTS never dropped` | стійка не вийшла з попереднього прийому; `START` натиснули зарано |
| `line did not take the first byte in N s` | вичерпався `--first`: стійка так і не ввійшла в прийом |
| `line did not take N/M B in N s` | вичерпався `--stall` посеред передачі. У BTR цього бути не має — там `--stall 0` |
| `no XOn after XOff` | вичерпався `--resume`. У BTR теж не має бути — там `--resume 0` |
| `more than one port` | портів кілька; назви потрібний через `--port /dev/ttyS0` |

Наприкінці передачі друкується хронологія `XOn`/`XOff` із мітками часу й
позиціями в байтах — видно, на якому наповненні буфера стійка спинила потік і
скільки його відпрацьовувала. Усе почуте з лінії лягає в `tapes/send_*.heard`
одразу, на першому ж байті.

## Алярми стійки при заливці

| № | Що це |
|---|---|
| `22` | таймаут — тиша 60 с, я не почав або лінія мовчить. **Не формат** |
| `30` | памʼять під програми скінчилась |
| `31` | нема вільного номера — директорію розмічено з чужими MD |
| `32` | помилка формату кадру |
| `33` | програма з таким номером уже є й відрізняється |

Гасяться поверненням у меню з `DATEN EIN-AUS` або софткнопкою `STOP`, не `RESET`.
