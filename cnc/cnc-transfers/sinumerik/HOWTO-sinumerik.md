# `./sinumerik` — сам інструмент обміну

Це двигун. На щодень зручніше через обгортки — [`./send`](HOWTO-send.md) і
[`./recv`](HOWTO-recv.md), — бо типові значення самого інструмента цій стійці
не підходять. Сюди лізь, коли треба щось нетипове.

```
./sinumerik [глобальні] {ports|lines|send} [прапорці підкоманди]
```

**Глобальні прапорці стоять ПЕРЕД підкомандою.** `./sinumerik --port /dev/ttyS0 send …`,
а не навпаки — інакше argparse відмовляє. Обгортка `./send` це переставляє сама.

## Підкоманди

### `ports` — які порти є в системі

```
./sinumerik ports
```

Порт **не відкривається**: читається `/sys/class/tty/*/type`. Це навмисно —
відкритий порт у цеху може бути чужим сеансом передачі, у який лізти не можна.
Порожні `ttyS0..S3`, за якими нема заліза (`type=0`), у список не потрапляють.
`ttyACM*` ігноруються окремим рядком: за ними і модем, і Arduino, і сканер
відбитків, відрізнити звідси справжній перехідник неможливо.

### `lines` — стан модемних ліній

```
./sinumerik lines -n 20
```

Показує CTS/DSR/DCD. Для цієї стійки:

* **CTS = «я в режимі прийому»**, а не «я готова до наступного файлу». У спокої 0,
  піднімається щойно оператор увів стійку в прийом. Насправді це її RTS.
* **DSR** — довго був 0 завжди; піднявся, коли інтерфейс ініціалізований.
* **DC1/DC3 від цієї стійки на вході не буває ніколи**: у звичайному прийомі вона
  line-controlled, потоком керує її RTS.

### `send` — віддати файл

```
./sinumerik send --gcode --gate 90 --wait 0 --stall 1000 файл.nc
```

Прапорці й типові значення:

| Прапорець | Типово | Що робить |
|---|---|---|
| `--gcode` | вимкнено | розбір під керуючу програму: ріже на кадри, знімає пробіли поза коментарями, `CRLF` на кожен кадр, лідер до `%` геть, `EOT` зберігає |
| `--trim-tail` | вимкнено | файли відновлення (TEA/PLC/ASM): відкинути хвіст-padding після `M02`/`M17`, завершити на `CRLF` |
| `--gate` | `0` | чекати `START`: перший файл по `CTS=1`, решта по переходу `1→0→1` |
| `--wait` | `20` | скільки чекати `DC1` перед стартом; `0` = слати одразу |
| `--xon-start` | вимкнено | не слати жодного байта, поки стійка не надішле `Xon`. Ця стійка його не шле, тож для робочих процедур не потрібен |
| `--first` | `90` | скільки чекати, поки лінія візьме **перший** байт; `0` = без межі |
| `--stall` | `0` | те саме **після** першого байта; `0` = чекати скільки треба |
| `--resume` | `0` | скільки чекати `XOn` після `XOff`; `0` = чекати скільки треба |
| `--eot` | нема | дописати байт кінця передачі, напр. `--eot 0x04` |
| `--linger` | `0` | слухати лінію після кінця; почуте лягає в `tapes/send_*.heard` |
| `--chunk` | `16` | розмір шматка запису |
| `--logdir` | `tapes/` | куди класти `.heard` |

Порядок розбору: `--gcode` **переважає** `--trim-tail`. Задавати обидва
безглуздо — `--trim-tail` буде проігноровано.

**Для BTR теж `--gcode`.** Окремого DNC-формату в потоці не існує: кадри ті
самі, разом із `%MPF…`-заголовком, по якому стійка звіряє номер програми з тим,
що вибрано на екрані AUTOMATIC (аларм 33). Набір параметрів під BTR підставляє
обгортка — `./send --dnc`.

**Три таймаути, і вони про різне.** `--first` стереже перший байт: поки він не
пройшов, ніщо не доводить, що стійка в прийомі. `--stall` і `--resume` стережуть
те, що після нього, і в BTR обидва мусять бути `0` — пауза там означає повний
circular buffer, тобто верстат працює, а не збій.

## Глобальні прапорці

| Прапорець | Типово | Примітка |
|---|---|---|
| `--port` | авто | без нього порт шукається сам, і **лише якщо він один**. Кілька — повна відмова зі списком |
| `--baud` | `9600` | |
| `--bits` | `7` | |
| `--parity` | `even` | |
| `--stopbits` | `1` | |
| `--no-crtscts` | — | вимкнути апаратний хендшейк; для перевірки трипровідного кабелю |
| `--dtr` | — | підняти DTR. Цеховий CIMCO його **не** піднімає, Traub піднімає |

## Чому порт відмовляється вгадуватись

За трьома портами одного PC стоять три різні верстати. «Здогадався сам» там
означає «шлемо не на той верстат», тому при кількох портах інструмент
відмовляється працювати й друкує список. Який порт до якого верстата — у `NOTES.md`.

## Чого не робити

1. **Не гейтити подачу файлів по рівню CTS** — тільки по переходу `1→0→1`.
   2026-08-04 гейт по рівню пропустив три файли підряд за 23 с без жодного старту.
2. **Не закривати порт між файлами** — на стику зʼявляється сліпий проміжок на
   кілька секунд, і натиснутий у нього `START` губиться. Тому шість файлів
   відновлення — це один виклик, а не шість.
3. **Не пояснювати відмову стійки форматом заголовка**, доки не подивився, на
   якому байті вона впала.
4. **Не автоматизувати прапорцями те, що можна визначити з файлу.** Кінці рядків,
   пробіли, `EOT` інструмент розбирає сам.
