# `./sniff` — послухати лінію й сказати, що на ній (СТ-161 NC)

Діагностика, не транспорт. **На диск не пише нічого.** Слухає порт, друкує стан
модемних ліній і статистику, з якої видно реальний формат на дроті.

Щоб зберегти програму у файл — це [`./recv`](HOWTO-recv.md), не `sniff`.

## Найкоротше

```
cd ~/cnc-transfers/ct161
./sniff
```

## Коли він потрібен

* **не знаємо швидкість або формат** — `sniff` визначає їх за самими байтами;
* **не знаємо, чи взагалі щось приходить** — видно момент першого байта;
* **треба побачити, як стійка рухає лініями** — CTS/DSR/DCD друкуються при
  кожній зміні, з номером байта, на якому вона сталась;
* **прийом обривається зарано** — `longest gap` показує, чи вистачає `--idle`.

## Чому 8N1, коли лінія 7E1

Свідомо. Біт парності приходить як восьмий біт даних, і його можна перевірити
програмно. Якщо ж виставити парність у ядрі, збійні байти підмінюються на `0x00`
і стають невідрізненними від справжніх нулів — тобто ми втратимо саме ту
інформацію, заради якої слухаємо.

Другий стоп-біт на прийомі ролі не грає, це просто зайвий простій лінії.

## Що він друкує

```
port /dev/ttyS0, 4800 8N1 raw
lines at start: CTS=0  DSR=1  DCD=0
waiting for data (up to 600 s)...
[   0.6s] data started

received: 675 B in 16.6 s
longest gap inside the data: 0.45 s at byte 260 (--idle is 1.50 s)

-- format on the wire --
  even number of 1s    : 675/675 = 100.0%
  8th bit set          : 191/675 = 28.3%
  printable as is      : 33.6%
  printable after &0x7F: 61.9%
  VERDICT: 7 bits + EVEN parity (8th bit is the parity bit)

-- most frequent bytes --
  0x00 x257   low7=0x00 .
  0x30 x91    low7=0x30 '0'
  0xA0 x82    low7=0x20 ' '
  …
-- first 500 characters (low7) --
-- last 200 --
```

## Як читати вердикт

| Вердикт | Що робити |
|---|---|
| `7 bits + EVEN parity` | те, що очікуємо за `NOTES.md` (4800 7E2); `recv` зніме восьмий біт сам |
| `7 bits + ODD parity` | не наш формат, дивись налаштування порту верстата |
| `8 bits, no parity (8N)` | восьмий біт — дані, знімати його не можна |
| `sample too small to judge` | прийшло менше 32 байт або менше 3 різних. Серія `0x00` має парну парність за будь-якого формату й не доводить нічого |
| `does not add up` | **найімовірніше не та швидкість.** Спробуй інший `-b` |

## DTR і RTS

Піднімаються одразу при відкритті порту й тримаються до кінця: для керування з
апаратним хендшейком це означає «периферія готова приймати».

CTS для прийому не потрібен: він обмежує лише **нашу** передачу.

**Усе це на цьому верстаті не перевірено.** До СТ-161 ми ще не доходили —
верстат заблокований і чекає оператора.

## Прапорці

| Прапорець | Типово | Для чого |
|---|---|---|
| `--ports` | — | показати порти й вийти, **не відкриваючи їх** |
| `--port` | авто | коли портів кілька |
| `-b` | `4800` | швидкість; перебирати, коли вердикт `does not add up` |
| `--wait` | `600` | скільки чекати першого байта |
| `--idle` | `1.5` | скільки тиші означає кінець даних |
| `--dc1` | вимкнено | слати `DC1` кожні 2 с — для керувань, які чекають Xon |

## Копія в кожному каталозі верстата

`sniff` навмисно продубльований у `traub/`, `ct161/` і тут. Каталог верстата має
переноситись на робоче місце цілим і працювати сам, без нічого ззовні. Відрізняються
копії трьома рядками: назвою верстата й типовою швидкістю.

Дивись також: [HOWTO-recv.md](HOWTO-recv.md), `NOTES.md`.
