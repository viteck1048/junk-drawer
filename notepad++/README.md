# notepad++ build scripts

Notepad++ (з плагіном **NppExec**, F6 — "Execute") як заміна повноцінних IDE.
Цей набір використовувався з 1 курсу бакалавра аж до диплому магістра —
під різні предмети/мови без перевстановлення IDE щоразу.

Наразі неактуально як основне середовище (значно менше машин з Windows,
слабких планшетів типу Lenovo Miix 11 теж уже нема) — конфіг збережено
як архів того, на чому все писалось ці роки.

## Як це працює

`F6_scripts.txt` — вміст NppExec-макросів (Settings → Import; або вручну
Execute → Save current commands as..., по одному блоку `#назва` на пункт
меню NppExec). Кожен блок — окремий пункт меню "Execute", викликаний по F6,
під конкретну мову/тулчейн. Макроси лише виставляють змінні середовища й
викликають зовнішні `.bat`-скрипти — саму компіляцію/лінк роблять вони.

Батники (`comp_VS12.bat`, `trans.bat`, `trans_2.bat`, `link.bat`, `run.bat`)
викликаються з **жорстко зашитим** шляхом `C:\Program Files\Notepad++\...`
(бачиш в `F6_scripts.txt`) — тобто самі файли мають фізично лежати в теці
Notepad++, або треба поправити шлях в усіх блоках F6_scripts.txt.

## Потрібні програми (і чому шляхи такі, як є)

Усі шляхи в скриптах — абсолютні й підв'язані до того, що стояло на
конкретному ноуті. При відновленні на новій машині їх треба перевірити/
поправити під фактичні шляхи встановлення.

- **Notepad++** + плагін **NppExec** — сам рушій F6-макросів
- **JDK 16.0.2** — `C:\Program Files\Java\jdk-16.0.2\bin\{javac,java}.exe`
  (блок `#java`)
- **MinGW-w64** — `C:\Program Files\mingw64\bin\g++.exe`, статична лінковка
  libgcc/libstdc++ (блок `#mingv`)
- **NASM** — `C:\Program Files\NASM\nasm.exe`, формат об'єктника `win32`
  (блок `#nasm`)
- **NSIS** — `C:\Program Files (x86)\NSIS\makensisw.exe` (блок `#nsis`,
  збірка інсталятора — імовірно фінальний білд диплома)
- **Firebird 2.1** — клієнтські бібліотеки
  `Firebird_2_1\lib\{fbclient_ms,ib_util_ms}.lib`, підключаються в загальній
  гілці `link.bat` (без `FLAG`) разом з User32/Gdi32/shell32/ComCtl32/comdlg32
  — це лінк GUI-застосунку з БД (курсовий/дипломний проєкт)
- **Microsoft Visual Studio 12.0 (VS2013) toolset + Windows SDK v7.1A** —
  див. окремий пункт нижче, це не звичайна інсталяція

### Щодо MSVS

MSVS у цьому наборі — **не встановлена легально IDE**, а тека, скопійована
з ноутбука коліжанки (без інсталятора, без реєстрації в системі). Тому
скрипти ніколи не покладаються на те, що Visual Studio "стоїть" (не шукають
`vcvarsall.bat`, не читають реєстр/env, які створює нормальний інсталятор) —
натомість `comp_VS12.bat`, `trans.bat`, `trans_2.bat` вручну прописують
`PATH`/`INCLUDE`/`LIB` прямо на скопійовані підтеки:

```
PATH=...\Microsoft Visual Studio 12.0\VC\bin\;%PATH%
INCLUDE=...\Microsoft Visual Studio 12.0\VC\include\;...\Windows SDK\v7.1A\Include\
LIB=...\Microsoft Visual Studio 12.0\VC\lib\;...\Windows SDK\v7.1A\Lib\
```

Тобто MSVS тут використовувалась **виключно як джерело `cl.exe`/`link.exe`
й заголовків/бібліотек** — консольні утиліти збірки, а не як IDE. Сама
Visual Studio (GUI, проєкти `.sln`/`.vcxproj`) жодного разу не запускалась.

## Файли

| Файл | Що робить |
|---|---|
| `F6_scripts.txt` | набір NppExec-макросів: java / mingw(g++) / nasm+ms-link / nsis / msvs (ansi) / msvs-unicode / msvs-trans (тільки компіляція, без лінку, обидва варіанти) |
| `comp_VS12.bat` | найстаріший варіант: компіляція (`cl.exe /c /W3`) одного файла й одразу лінк з `User32.lib` в одному скрипті — попередник пари trans+link |
| `trans_2.bat` | компіляція одного `.cpp` через `cl.exe /c /W3 /EHsc` (ANSI, без unicode-дефайнів), попередній `.obj` перейменовує в `_old` |
| `trans.bat` | те саме, але unicode-збірка (`/D UNICODE /D _UNICODE`) + `/FA` (лістинг асемблера) |
| `link.bat` | лінкер, дві гілки по змінній `FLAG`: якщо `FLAG` задано ("qwerty") — мінімальний консольний лінк без CRT (`/nodefaultlib /entry:main`, тільки Kernel32/User32/msvcrt) — гілка nasm; якщо `FLAG` не задано — збирає **всі** `.obj` у теці (крім поточного і `_old`) і лінкує їх разом з Firebird + GUI-бібліотеками — гілка msvs (багатофайловий GUI-проєкт) |
| `run.bat` | запускає зібраний `.exe`; якщо `FLAG` задано — шукає `_gcc.exe` (гілка mingw), інакше звичайний `.exe` |
